# پراکسی API گفت‌وگوی وب DeepSeek

[English](README_en.md) · [فارسی](README_fa.md)

> پراکسی غیررسمی برای تبدیل پروتکل خصوصی وب‌سایت `chat.deepseek.com` به APIهای سازگار با OpenAI و Anthropic.

**مهم:** این پروژه به وب‌اپ DeepSeek متصل می‌شود، نه API رسمی `api.deepseek.com`. برای کار به توکن و کوکی‌های یک حساب وبِ واردشده نیاز دارد و چالش اثبات کار وب‌کلاینت را حل می‌کند. پروتکل مستند نیست و ممکن است هر زمان تغییر کند. این پروژه وابسته به DeepSeek نیست؛ مسئولیت استفاده و رعایت شرایط سرویس بر عهدهٔ شماست.

## سازگاری مدل‌های DeepSeek

طبق صفحهٔ رسمی [مدل‌ها و قیمت‌ها](https://api-docs.deepseek.com/quick_start/pricing/)، API رسمی `deepseek-flash` را به‌عنوان V4.1-Flash دارای قابلیت بینایی و `deepseek-v4-pro` را به‌عنوان V4-Pro-0813 متنی فهرست می‌کند. [تاریخچهٔ رسمی به‌روزرسانی‌ها](https://api-docs.deepseek.com/updates/) ادامهٔ سرویس API مدل Pro را نیز اعلام می‌کند. این مدل‌های API را نباید با حالت‌های رابط وب یکی دانست.

تجربهٔ وب DeepSeek گزارش شده که حالت‌های سریع، تخصصی و بینایی را در یک تجربهٔ تطبیقی ترکیب کرده است ([گزارش AIbase](https://www.aibase.com/news/30949)). این گزارش قرارداد رسمی برای پروتکل خصوصی وب نیست و رفتار فعلی آن در این پراکسی زنده‌آزمایی نشده است.

پیکربندی پیش‌فرض محلی فقط یک نام مستعار مسیر دارد:

| شناسهٔ مدل سمت کلاینت | مسیر محلی | توضیح |
|---|---|---|
| `deepseek-flash` | `default` | راهنمای پیش‌فرض برای مسیر خصوصی گفت‌وگوی وب |

`deepseek-flash` به `api.deepseek.com` فرستاده نمی‌شود و نام مدل برگشتی، هویت مدل واقعیِ انتخاب‌شده در وب‌اپ را اثبات نمی‌کند. این پراکسی فعلاً **فقط متن** را می‌فرستد. ورودی‌های تصویری و چندرسانه‌ای OpenAI و بلوک‌های تصویر Anthropic با HTTP 400 رد می‌شوند تا بی‌صدا حذف نشوند. برای پردازش تصویر از API رسمی DeepSeek استفاده کنید.

## امکانات

- `POST /v1/chat/completions` و `GET /v1/models` سازگار با OpenAI، با پشتیبانی از پاسخ جریانی.
- `POST /v1/messages` سازگار با قالب Anthropic.
- احراز هویت کلید API کلاینت از طریق `Authorization: Bearer` یا `x-api-key`.
- مسیر پیش‌فرض محلی و راهنماهای قدیمیِ قابل تنظیم برای حالت تفکر و جست‌وجو؛ اثر فعلی این راهنماها روی پروتکل خصوصی تأیید نشده است.
- فراخوانی ابزار مبتنی بر دستورهای DSML به‌صورت best-effort؛ پشتیبانی بومی یا تضمین‌شده نیست.
- حل خودکار چالش اثبات کار، مدیریت نشست و استفادهٔ اختیاری از نشست چندمرحله‌ای.
- مخزن چندحسابی، محدودسازی نرخ درخواست، تخمین مصرف و پنل مدیریت.
- امکان رمزگذاری Fernet برای اطلاعات حساب ذخیره‌شده.
- رابط وب با انتخاب زبان **English / فارسی**؛ حالت فارسی چیدمان راست‌به‌چپ (RTL) دارد.
- ابزار اختیاری Chromium برای ثبت یک‌بارهٔ توکن و سرآیند Cookie حساب خودتان؛ اطلاعات فقط به‌صورت محلی کپی می‌شود. [راهنمای فارسی ابزار](tools/chromium-credential-capture/README_fa.md)
- نصب‌کنندهٔ کاربرمحور که فرمان `ds2api` را بدون دسترسی مدیر سیستم به PATH اضافه می‌کند.

## پیش‌نیازها

- Python نسخهٔ 3.10 یا جدیدتر.
- دسترسی شبکه به `chat.deepseek.com` و endpointهای امضای خصوصی مورد استفادهٔ adapter.
- حساب معتبر DeepSeek و توکن/کوکی‌های فعال آن.
- Node.js نسخهٔ 20 یا جدیدتر و npm برای ساخت رابط WebUI، اگر فایل‌های build موجود نباشند. برای استفادهٔ صرفاً API، Node.js لازم نیست.

## شروع سریع

### ۱. دریافت پروژه و نصب

```bash
git clone https://github.com/Rezayavarzade123/deepseek-web2api-free-test.git
cd deepseek-web2api-free-test
```

نصب‌کنندهٔ کاربرمحور (بدون نیاز به دسترسی مدیر سیستم):

```powershell
# Windows PowerShell
py -3 scripts\install.py
```

```bash
# macOS / Linux
python3 scripts/install.py
```

نصب‌کننده محیط مجازی می‌سازد، وابستگی‌های Python را نصب می‌کند، در صورت وجود Node.js 20+ رابط WebUI را می‌سازد و فرمان `ds2api` را به PATH کاربر اضافه می‌کند. پس از نصب یک ترمینال جدید باز کنید و `ds2api` را اجرا کنید. در نصب نخست، گذرواژهٔ مدیر به‌صورت تصادفی ساخته و فقط یک‌بار نمایش داده می‌شود؛ آن را امن نگه دارید. اجرای دوبارهٔ نصب‌کننده برای به‌روزرسانی، فایل `.env` و پوشهٔ `data/` را حفظ می‌کند.

اگر Node.js نصب نباشد، نصب در حالت API-only کامل می‌شود. برای ساخت WebUI، Node.js 20+ نصب و نصب‌کننده را دوباره اجرا کنید؛ برای ردکردن ساخت WebUI نیز `--skip-webui` را به فرمان نصب اضافه کنید.

برای حذف نصب، از Python سیستم (نه Python محیط مجازی برنامه) استفاده کنید: در PowerShell ویندوز `py -3 "$env:LOCALAPPDATA\Programs\DS2API\scripts\uninstall.py"` و در macOS/Linux `python3 ~/.local/share/ds2api/scripts/uninstall.py` را اجرا کنید. فرمان PATH و فایل‌های برنامه حذف می‌شوند، اما `.env` و `data/` باقی می‌مانند. فقط اگر می‌خواهید تنظیم‌ها و اطلاعات حساب هم حذف شوند، `--purge-user-data` را اضافه کنید. اگر هنگام نصب `--install-dir` سفارشی تعیین کرده‌اید، همان مسیر را جایگزین کنید.

راه‌اندازی دستی از checkout برای توسعه نیز ممکن است:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

در ویندوز، `start.bat` هم برای اجرای مستقیم از checkout در دسترس است.

### ۲. پیکربندی امن

نصب‌کننده فایل `.env` را می‌سازد و گذرواژهٔ مدیر قوی و تصادفی تولید می‌کند؛ آن را بازنویسی نکنید. در نصب دستی، ابتدا فایل نمونه را کپی کنید:

```bash
cp .env.example .env
```

فایل `.env` را ویرایش کنید. برای اجرای محلی `HOST=127.0.0.1` را نگه دارید و یک گذرواژهٔ قوی و منحصربه‌فرد برای `DEEPSEEK_ADMIN_PASSWORD` تعیین کنید. مقدار پیش‌فرض `admin` را پیش از هرگونه دسترسی از شبکه تغییر دهید.

مسیر محلی پیش‌فرض:

```ini
MODEL_NAME=deepseek-flash
MODEL_ROUTES={"deepseek-flash":"default"}
HOST=127.0.0.1
PORT=8080
ALLOW_UNAUTHENTICATED_API=false
```

`MODEL_ROUTES` نام مستعارهای کلاینت را به راهنماهای خصوصی وب‌چت نگاشت می‌کند؛ شناسهٔ مدل رسمی API نیست. تنظیمات کامل در `.env.example` آمده است.

### ۳. افزودن حساب وب DeepSeek

۱. در مرورگر به [chat.deepseek.com](https://chat.deepseek.com) وارد شوید.
۲. ابزار توسعهٔ مرورگر را با `F12` باز کنید و زبانهٔ **Network** را انتخاب کنید.
۳. در وب‌سایت یک پیام بفرستید و درخواست گفت‌وگوی مربوط را باز کنید.
۴. از **Request Headers** مقدار `Authorization` را بردارید: فقط مقدار بعد از `Bearer ` را در فیلد Token بگذارید. کل مقدار `Cookie` را نیز در فیلد Cookies وارد کنید.
۵. این دو مقدار را در **WebUI → Account Pool → Add account** ثبت کنید.

در Chrome، Edge یا Brave می‌توانید از [ابزار اختیاری ثبت یک‌بارهٔ اعتبارنامه](tools/chromium-credential-capture/README_fa.md) استفاده کنید: پس از فعال‌کردن دستی ابزار، درخواست بعدیِ منطبق را می‌گیرد و فقط با زدن دکمه‌های کپی، مقادیر را در کلیپ‌بورد می‌گذارد؛ چیزی را بارگذاری یا ارسال نمی‌کند.

این توکن و کوکی‌ها مانند گذرواژه هستند: فقط از حساب خودتان استفاده کنید، آن‌ها را در همین دستگاه وارد کنید، در مخزن عمومی ذخیره نکنید و در گفتگو نفرستید. اعتبارشان ممکن است منقضی یا لغو شود.

### ۴. اجرا و ساخت کلید کلاینت

اگر از نصب‌کننده استفاده کرده‌اید، در یک ترمینال جدید `ds2api` را اجرا کنید؛ این فرمان در PATH کاربر ثبت شده است. برای اجرای دستی از checkout، در ویندوز می‌توانید از `start.bat` استفاده کنید یا از ریشهٔ پروژه اجرا کنید:

```powershell
.\.venv\Scripts\python.exe -m uvicorn server:app --host 127.0.0.1 --port 8080
```

یا در macOS/Linux:

```bash
.venv/bin/python -m uvicorn server:app --host 127.0.0.1 --port 8080
```

در مرورگر، [http://127.0.0.1:8080/webui/](http://127.0.0.1:8080/webui/) را باز کنید و با گذرواژهٔ مدیر وارد شوید. در **Account Pool** وضعیت حساب را بررسی کنید؛ سپس از **Playground** یک پیام متنی بفرستید. برای انتخاب فارسی، دکمهٔ زبان را بزنید؛ انتخاب زبان در مرورگر ذخیره می‌شود.

برای استفاده از SDK یا ابزار خارجی، در **Settings** یک کلید API بسازید. کلید کامل فقط یک‌بار نمایش داده می‌شود؛ آن را امن نگه دارید. سلامت سرور و مدل‌های قابل انتخاب را بررسی کنید:

```bash
curl http://127.0.0.1:8080/health
curl http://127.0.0.1:8080/v1/models \
  -H "Authorization: Bearer YOUR_CLIENT_API_KEY"
```

### ۵. درخواست متنی آزمایشی

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer YOUR_CLIENT_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"deepseek-flash","messages":[{"role":"user","content":"سلام! لطفاً فقط بنویس: پراکسی کار می‌کند"}],"stream":false}'
```

پاسخ باید حاوی `choices` باشد. مقدار `model` در پاسخ، نام مستعار ارسالی از کلاینت است و مدل واقعی بالادستی را تأیید نمی‌کند.

### آزمون ورودی تصویر

این شاخه پردازش تصویر ندارد. اگر پیام OpenAI دارای بخش `image_url` یا درخواست Anthropic دارای بلوک `image` بفرستید، پاسخ مورد انتظار **HTTP 400** است؛ تصویر نباید بی‌صدا نادیده گرفته شود.

## مرجع API

### `POST /v1/chat/completions`

بدنهٔ درخواست با قالب OpenAI Chat Completions سازگار است:

| فیلد | نوع | توضیح |
|---|---|---|
| `model` | رشته | نام مستعار مسیر کلاینت؛ پیش‌فرض از `MODEL_NAME` می‌آید. |
| `messages` | آرایه | الزامی؛ پیام‌های system، user، assistant و tool. فقط متن پذیرفته می‌شود. |
| `stream` | بولی | فعال‌کردن پاسخ جریانی به قالب OpenAI SSE. |
| `thinking_mode` | بولی | درخواست خروجی تفکر در صورت پشتیبانی بالادستی؛ اثر فعلی تأیید نشده است. |
| `search_enabled` | بولی | راهنمای خصوصی جست‌وجوی وب؛ اثر فعلی تأیید نشده است. |
| `tools` | آرایه | تعریف تابع OpenAI که به دستور DSML تبدیل می‌شود؛ best-effort. |
| `tool_choice` | رشته/شیء | راهنمای متنی برای انتخاب ابزار؛ انتخاب اجباری تضمین نمی‌شود. |
| `user` | رشته | شناسهٔ اختیاری و پایدار برای استفادهٔ مجدد از نشست چندمرحله‌ای. |
| `temperature`، `top_p`، `max_tokens` | عدد | برای سازگاری پذیرفته می‌شوند، اما به وب‌کلاینت فرستاده نمی‌شوند. |

در حالت stream، خروجی به شکل قطعه‌های OpenAI ارسال و با `data: [DONE]` تمام می‌شود. اگر خروجی reasoning در دسترس باشد، در `reasoning_content` می‌آید. مقدارهای usage تخمین محلی هستند، نه شمارش رسمی بالادستی.

### `POST /v1/messages`

adapter سازگار با قالب Anthropic Messages است. فیلدهای پیام، سیستم، ابزار، stream و thinking را می‌پذیرد؛ تصویر پشتیبانی نمی‌شود و با HTTP 400 رد می‌شود. جزئیات کامل فیلدها و مثال‌ها در [راهنمای انگلیسی](README_en.md) آمده است.

### `GET /v1/models`

شناسه‌های تعریف‌شده در `MODEL_ROUTES` را برمی‌گرداند؛ اگر جدول مسیر خالی باشد، `MODEL_NAME` برگردانده می‌شود.

### نشست‌های چندمرحله‌ای

استفادهٔ مجدد از نشست فقط با شناسهٔ ثابت کلاینت انجام می‌شود: `X-Conversation-Id`، فیلد OpenAI با نام `user` یا `metadata.user_id` در Anthropic. کلید cache به کلاینت محدود است و نشست بالادستی به همان حسابی که آن را ایجاد کرده متصل می‌ماند. بدون شناسه، هر درخواست نشست تازه‌ای می‌سازد. برای غیرفعال‌کردن، `SESSION_CACHE_TTL=0` قرار دهید.

## تنظیمات پرکاربرد

| متغیر | پیش‌فرض | کاربرد |
|---|---|---|
| `HOST` | `127.0.0.1` | نشانی گوش‌دادن؛ برای استفادهٔ محلی همین مقدار امن است. |
| `PORT` | `8080` | پورت سرور. |
| `DEEPSEEK_ADMIN_PASSWORD` | `admin` | گذرواژهٔ پنل؛ پیش از استفادهٔ عمومی تغییر دهید. |
| `ALLOW_UNAUTHENTICATED_API` | `false` | فقط برای توسعهٔ محلی؛ برای سرویس عمومی فعال نکنید. |
| `MODEL_NAME` | `deepseek-flash` | نام fallback در پاسخ‌ها و `/v1/models`. |
| `MODEL_ROUTES` | `{"deepseek-flash":"default"}` | نام مستعار محلی به راهنمای خصوصی؛ `expert` راهنمای قدیمی و تأییدنشده است. |
| `MODE` | `auto` | راهنمای حالت خصوصی؛ اثر فعلی `expert` در وب‌اپ تأیید نشده است. |
| `THINKING` | `auto` | مقدارهای `auto`، `enabled` یا `disabled`. |
| `SEARCH` | `auto` | مقدارهای `auto`، `enabled` یا `disabled`. |
| `ACCOUNT_STORE_PATH` | `data/accounts.json` | مسیر فایل مخزن حساب. |
| `DEEPSEEK_ENCRYPTION_KEY` | تنظیم‌نشده | کلید Fernet برای رمزگذاری توکن/کوکی در حالت سکون. |
| `SESSION_CACHE_TTL` | `1800` | عمر نشست cache بر حسب ثانیه؛ `0` برای غیرفعال‌سازی. |
| `CLIENT_RPM_PER_KEY` | `60` | سقف درخواست در دقیقه برای هر کلید API؛ `0` بدون محدودیت این بُعد. |
| `CLIENT_RPM_PER_IP` | `120` | سقف درخواست در دقیقه برای هر IP؛ `0` بدون محدودیت این بُعد. |
| `ALLOWED_ORIGINS` | خالی | فهرست مبدأهای مجاز CORS؛ خالی یعنی فقط same-origin. |

## امنیت و استقرار

- گذرواژهٔ مدیر پیش‌فرض را عوض کنید؛ `ALLOW_INSECURE_PUBLIC_DEFAULTS` را روی سرور عمومی فعال نکنید.
- برای دسترسی خارج از دستگاه، HTTPS و reverse proxy امن راه‌اندازی کنید؛ سرور را بی‌محافظ روی اینترنت منتشر نکنید.
- `ALLOW_UNAUTHENTICATED_API=false` را نگه دارید و برای کلاینت‌ها کلیدهای جدا بسازید.
- با `DEEPSEEK_ENCRYPTION_KEY` اطلاعات حساب را در حالت سکون رمزگذاری کنید و از کلید در مکانی جدا پشتیبان بگیرید.
- دسترسی به `data/accounts.json`، `data/api_keys.sqlite3` و پوشهٔ `data/` را محدود کنید.
- توکن و کوکی حساب وب DeepSeek را مانند گذرواژه نگه دارید و در صورت افشا، آن‌ها را تازه‌سازی/لغو کنید.

## توسعه و آزمون‌ها

آزمون‌های محلی به اطلاعات ورود DeepSeek یا شبکهٔ upstream نیاز ندارند:

```bash
python -m pip install -r requirements.txt
python -m pytest
python -m tests.smoke
python scripts/run_e2e.py
```

برای ساخت WebUI با Node.js:

```bash
cd webui-new
npm ci
npm run build
```

رفتار پروتکل خصوصی `chat.deepseek.com` هنوز زنده‌آزمایی نشده است. آزمون‌های محلی فقط رفتار خود پراکسی را بررسی می‌کنند. برای توضیحات کامل API، پرسش‌های رایج و مرجع همهٔ متغیرها، [راهنمای انگلیسی](README_en.md) را ببینید.
