# v3.3.6-rc.3 — Manage client API keys in the WebUI (pre-release)

> 2026-10-03 · release candidate

## Added

- The WebUI **Settings** page can create multiple client API keys, copy a new key, show each key's prefix and creation time, and revoke keys individually.
- The complete key is returned only once. The server stores only its SHA-256 hash in `data/api_keys.sqlite3`.
- Legacy `API_KEYS` / `DEEPSEEK_API_KEY` values in `.env` are imported once when the key database is first initialized. API authentication is managed by the database afterward.
- The service version returned by the admin API is updated to `3.3.6-rc.3`.

## Fixes and validation

- If `.env` does not exist at startup, `start.bat` now creates it from `.env.example`.
- Added tests for API-key storage, one-time import, admin endpoints, and `/v1` authentication. These tests are included in the Python 3.10–3.12 CI matrix.
- Local validation passed: 108 pytest cases, the smoke test, and the end-to-end checks.
