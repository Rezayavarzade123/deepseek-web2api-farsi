# v3.3.6 — Client API-key management and unified account-pool configuration

v3.3.6 consolidates improvements from four release candidates, focusing on client API keys, startup usability, and account configuration.

## Added

- **WebUI client API-key management:** create multiple keys, view their prefixes and creation times, and revoke each key independently. The full key is shown only once; the server stores only its SHA-256 hash.
- **One-time import of legacy keys:** the first initialization of the API-key database can import legacy `API_KEYS` / `DEEPSEEK_API_KEY` values from `.env`.

## Improvements

- Startup output now shows the admin-password label and effective value on one line. If a system environment variable overrides `.env`, the override is shown; if no value is configured, the default `admin` is shown.
- The Windows launcher creates `.env` from `.env.example` if the file is missing.
- The WebUI build script checks for `tsc` and `vite` before building. It exits with a clear error if dependency installation fails or build tools are missing. When `package-lock.json` exists, it uses `npm ci` and suggests checking registry or proxy connectivity after installation failures.
- GitHub Releases created from version tags containing a hyphen (such as `v3.3.6-rc.1`) are marked as pre-releases.

## Account configuration changes

- Account credentials are configured only through the WebUI account pool or `data/accounts.json`. The service no longer reads legacy or indexed `DEEPSEEK_TOKEN`, `DEEPSEEK_COOKIES`, and `DEEPSEEK_EMAIL` variables, environment-variable account fallbacks, or per-account proxy settings.
- An empty account pool does not try to use credentials from environment variables and logs instructions for adding an account.
- Removed the WebUI's read-only environment-account status and source counts. `.env.example`, the English README, and maintainer notes have been updated.

> **Upgrade notice:** If DeepSeek credentials were previously stored in `.env`, migrate them to the WebUI account pool or `data/accounts.json` before upgrading. Legacy client API keys are imported once when the database is first initialized; verify that initialization succeeded before removing the old settings. A client key's full value is not shown again after creation, so save it securely when it is displayed.

- `v3.3.6-rc.4`: 103 pytest cases passed; TypeScript checks and the Vite production build passed.
